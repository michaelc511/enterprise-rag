S1:1 Data Sources: The Business, the Company, and the Documents

The Business: Third-Party Risk Management (TPRM)

Before a company lets a vendor touch its data, procurement, security, and GRC (governance, risk & compliance) teams read the vendor's contract and its SOC 2 audit report and check both against the company's own security policy. It's slow, manual, and high-stakes: one missed clause can mean customer data used to train someone else's AI model, or a breach the company hears about days too late. This product is a RAG assistant that does that review with cited answers, in two directions:

  • Inbound (vendor review): "Is this vendor safe?" Check a vendor's MSA and SOC 2 report against our policy and flag gaps.
  • Outbound (security questionnaires): "Prove we're safe." Answer a customer's security questionnaire with citations from our own policies.

It's used by procurement, security, GRC, legal, and sales teams. Not legal advice.

The Company: OpsVault (fictional)

What OpsVault does: it's a cloud enterprise workflow platform: one platform that runs a company's IT, HR, customer service, risk, finance, and supply-chain work, with AI agents built in. Customers buy ready-made products (SaaS) or build their own apps on the OpsVault Platform (PaaS).

How OpsVault works: it follows a Customer Zero approach. Its own teams use a product first, then it's sold to customers. This assistant follows the same path: OpsVault's GRC team reviews its own vendors with it first, then it ships as an OpsVault AI skill inside Risk & Compliance.

S1:7 Document-by-Document Walkthrough: How the Corpus Fits Together

  • Start with the policy. POL-SEC-007 is the yardstick. It defines a Critical Vendor (anyone touching Customer Data) and the eight vendor rules: SOC 2 Type II (VM-1), AES-256 at rest with yearly key rotation (VM-2), TLS 1.2+ (VM-3), 48-hour incident notice (VM-4), no AI training on customer data even if de-identified (VM-5), 30-day deletion (VM-6), a 2x-fees breach cap (VM-7), and a yearly audit right (VM-8).
  • The framework connects policy to SOC 2. POL-GRC-002 maps criteria like CC6.1 and CC7.4 to OpsVault controls, and lists the customer-facing commitments that outbound answers may use.
  • Stratocore is the "mostly good" vendor. Its MSA meets the policy on paper. Its NDA came first and is cited by the MSA. Its two SOWs both point back to MSA-2025-014. Its SOC 2 Type II is clean except for one key-rotation exception.
  • Cortexa is the "risky" vendor. Its MSA looks fine at §5.3 ("no model training") but §5.4 allows training on de-identified usage data. Its notice window, liability cap, and audit rights all fall short, and it only has a Type I report.
  • Harborline is a different kind of NDA. It adds non-solicitation and a rule for shipment personal data, so not every NDA question has the same answer.
  • The questionnaire flips the direction. Brightwater asks OpsVault to prove its own controls, including two questions (HIPAA, ISO 27001) whose honest answer is "No".

S1:9 System Design ↑ S1

Talking points for a system-design discussion.

  • Data: "What datasets would you use?" A curated synthetic corpus first, so every demo question and gap has a known answer; CUAD's lawyer-labeled contracts next, for realism and recall metrics.

S2:1 Document Loading: Every PDF Becomes Clean, Traceable Text

S2 turns the 11 PDFs from S1 into text the rest of the pipeline can read. Each page becomes a Document whose metadata says exactly where it came from, so every later answer can be traced back to a file and page.

The Big Picture: Load, Clean, Label

  • Load: walk raw/ recursively, one Document per page.
  • Clean: remove the "synthetic document" footer and page numbers, collapse extra spaces, drop blank pages.
  • Label: source is the path relative to raw/, so the folder (document type) is part of it; page starts at 1.

What's Imported (and Why)

  • pypdf.PdfReader (lazy): extracts each page's text.
  • langchain_core.documents.Document: the standard object every LangChain splitter and vector store accepts.
  • re: footer patterns and whitespace cleanup.

S3:7 Line-by-Line Deep Dive: Why These Numbers

  • CHUNK_SIZE = 1000 characters is roughly 200 words: one or two contract clauses. Small enough to be specific, big enough to keep a clause whole.
  • CHUNK_OVERLAP = 150 repeats the end of one chunk at the start of the next, so a clause cut at a boundary is still readable in one of them.
  • separators add ". " to the default list, so a cut prefers the end of a sentence over the middle of one.
  • The filter drops chunks that are only whitespace, so nothing empty gets embedded or retrieved.

S7:7 Line-by-Line Deep Dive: Build, Save, Load, Search

  • build_index() refuses an empty chunk list (a missing raw/ folder would otherwise build an empty index), embeds through FAISS.from_documents, and saves to the model-specific folder.

S7:8 Technical Deep Dive: What Vector Search Finds, and What It Misses

  • Finds meaning: "how fast must they tell us about a breach" matches "notify … within forty-eight (48) hours".
  • Misses exact terms: IDs like CC6.1, MSA-2025-014, or "Section 7.2" carry little meaning to an embedding model. S9 adds BM25 keyword search for these.
  • Exact search at this size: 56 vectors are searched exhaustively; approximate indexes (HNSW, IVF) only matter at tens of thousands.
  • langchain-community is being sunset. FAISS is the one part still using it; a standalone integration can replace it later.

S12:7 Line-by-Line Deep Dive: Inside answer()

  • from_config() loads the saved index (F3) and the chat model once, so chat doesn't reload per question.
  • No documents, no LLM call. If search returns nothing, the engine returns the refusal directly, so nothing gets answered from the model's memory.
  • prompt | self.llm builds the system and human messages and calls the model; .content is the answer text.
  • Answer holds the question, answer, sources, and engine name: everything the terminal, API, or UI needs.
  • get_engine() is the F12 switch: plain_rag now, langgraph with S17.

S12:8 Technical Deep Dive: What Grounding Prevents, and What It Doesn't

  • Prevents: answers with no source, and answers from general knowledge when the documents are silent (the ISO 27001 question tests this).
  • Doesn't guarantee: the model can still misread a chunk or cite the wrong number. S13 evals measure faithfulness.
  • Only as good as retrieval: if search misses the right chunk, the honest answer is the refusal. S8–S10 improve what gets retrieved.
  • No redaction yet: the fake PII in the documents can appear in answers until S5.

S12:9 System Design ↑ S12

Talking points for a system-design discussion.

  • Hallucination control: an exact refusal string makes "I don't know" testable and countable in evals
  • Agents: the engine interface means S17's LangGraph agent plugs in beside this one, behind the same ask and API
  • Evals: temperature 0 plus a fixed index means the same question gives the same answer, so regressions are visible
